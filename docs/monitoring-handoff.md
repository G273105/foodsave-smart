# Monitoring integration handoff — Team Green

Updated: 16 October 2026. Owner: Costel.

## Agreed sender contract

POST /api/temperatures every 30 seconds, Content-Type application/json and Authorization: Bearer <DEVICE_TOKEN>. Credentials remain private.

Normal physical reading:
```json
{"id":"esp32-01","temperature":24.1,"sensor_status":"ok"}
```
Sensor failure:
```json
{"id":"esp32-01","temperature":null,"sensor_status":"error"}
```
The simulator uses simulator-01. Temperature is Celsius; valid readings are finite numbers. Humidity is display-only. Receipt timestamps are generated by the backend in UTC; the ESP32 display uses UK local time.

## Current backend contract checked on GitHub

Reference: PR #3, branch feature/laurentiu-marius-carlan-backend, commit 00f7e9f62866cffce51e718c95f72f44f3d61c53, backend/API_CONTRACT.md and backend/db.py.

The backend now uses MySQL (fridge_db), replacing the earlier SQLite integration plan. The contract maps simulator-01 to device_id 1 and esp32-01 to device_id 2; both belong to Fridge 1 (location_id 1). The simulator remains the primary source for SAFE/HOLD. Physical ESP32 readings are stored but do not change safety state.

The current contract requires null for sensor_status error and documents HTTP 201 for accepted/stored readings, HTTP 401 for authentication errors and HTTP 503 for database failures. The earlier numeric-error validation finding is historical; this updated backend has not been retested here.
